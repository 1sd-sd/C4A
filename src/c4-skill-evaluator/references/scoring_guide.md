# 评分标准全公开（scoring_guide）

> 本文件是 `c4-skill-evaluator` 的评分说明书。**任何人拿到一份提交，都可以按本文手算出与评审器一致的数字。**
> 所有信号、权重、阈值、封顶值都在 `references/c4a_rubric.json` 里，评审器不含任何评审硬编码。

---

## 一、总公式

```
最终分 = min( 完整性比率 × 0.4 + 质量比率 × 0.6 ) × 100 , 红旗封顶值 )
```

| 分量 | 计算方式 |
|------|----------|
| 完整性比率 | Σ（各交付物权重 × 状态系数），状态系数：✅=1.0、⚠️=0.5、❌=0 |
| 质量比率 | Σ（各维度得分率 × 维度权重），四个维度权重各 0.25 |
| 红旗封顶 | 取所有命中红旗的 `cap_score` 最小值 |

等级：≥85 A（优秀）｜≥70 B（良好）｜≥55 C（及格）｜<55 D（需返工）

## 二、完整性：5 类必须交付物

| 交付物 | 权重 | 文件名信号 | 可接受扩展名 | 内容信号（需 ≥2 命中） |
|--------|------|-----------|-------------|----------------------|
| 可执行内容 | **0.30** | skill / 技能 / checker / evaluator / mapper / explainer / generator / tool | .skill .py .zip .sh .js .md .ipynb | ` ``` ` `def ` `class ` `import ` workflow 工作流 |
| Skill 说明文档 | 0.25 | skill说明 / skill_doc / skill-doc / skill_description / 技能说明 | .md .docx .pdf .txt | 使用场景 解决什么问题 输入 输出 适用场景 |
| Demo | 0.15 | demo / 演示 / 截图 / 录屏 / screen / screenshot / 运行结果 | .mp4 .mov .webm .png .jpg .jpeg .gif .md | （仅文件名与扩展名） |
| 教学说明 | 0.15 | 教学说明 / 教学 / 上手指南 / tutorial / teaching / quickstart / how-to / 使用说明 | .md .docx .pdf .txt | 上手 步骤 常见坑 安装 注意事项 |
| AI 日志 | 0.15 | AI日志 / AI_log / ai-log / ai_日志 / ai使用记录 | .md .docx .pdf .txt | 使用的 AI AI 工具 prompt 迭代 ChatGPT Claude DeepSeek Cursor |

**打分与分配规则**

1. 文件名信号每命中 +3.0；扩展名命中 +1.0；内容信号每条 +0.5（上限 +2.0）。
2. **`accept_ext` 是硬过滤**：扩展名不在白名单里，该 (文件 × 交付物) 对直接得 0 分。
   没有这一层，`rubric.yaml` 里因为写着「输入」「输出」这些**规范词**就会被误判成 Skill 说明文档。
3. **强证据扩展名**：`.skill / .py / .zip / .sh / .js / .ipynb` 一旦命中即视为强匹配——这类文件本身在语义上就是"可执行内容"。
4. 全部 (文件 × 交付物) 对按分数**降序贪心分配**，每个文件只能填一个槽位。
   这防止一份 README 同时被记成三类交付物。
5. 强匹配阈值 3.0，弱匹配阈值 1.5：`≥3.0 → ✅`；`≥1.5 → ⚠️`；否则不匹配。
6. 命中文件的字节数 **< 32 B** → 判为**空壳**，该槽位强制降为 ⚠️，并计入「核心交付物缺失」红旗的分母。
   —— 只交了占位符，等于没交。

## 三、质量：四条件

每个维度拆成 4–5 条**可判定**检查项。每项给 `pass=1.0 / partial=0.5 / fail=0 / na（不计入分母）`。

```
维度得分率 = 该维度所有"适用检查项"的得分之和 ÷ 适用检查项条数
评级：得分率 ≥ 0.80 → ✅ ；≥ 0.40 → ⚠️ ；否则 ❌
关键项一票否决：任一"关键项"未 pass，则该维度最高只能到 ⚠️
```

「关键项」= 失守即等同于"别人根本用不了"的项，共 5 条（在 JSON 中标记 `critical: true`）：

| 维度 | 关键项 | 为什么关键 |
|------|--------|-----------|
| 可复用 | 可执行文件内无硬编码绝对路径 | 换台机器就跑不起来 |
| 可执行 | 技能包结构合法 | 伪包 = 装上也是空的 |
| 可执行 | SKILL.md 有有效 frontmatter | 没有 name/description，技能**永远不会被触发** |
| 可验证 | Demo 存在且非空 | 没法证明它真的跑过 |
| IO 明确 | 有「输入X，输出Y」一句话 | 使用者不知道要喂什么 |

### 可复用（Reusable）

| 检查项 | 判定规则 |
|--------|----------|
| 有安装 / 上手步骤 | 关键词：安装 / 使用步骤 / pip install / npm install / install / 上手 / getting started / 解压 |
| 可执行文件内无硬编码绝对路径 **（关键）** | 在**代码文件**里正则匹配 `C:\ D:/ /Users/ /home/xxx /mnt/ UNC共享`，命中即 ❌ |
| 文档内绝对路径仅作示例 | 在**文档**里同样匹配：≤4 处 → ✅；5–20 处 → ⚠️；>20 处 → ❌ |
| 声明了运行环境 / 依赖 | 关键词：环境要求 / 依赖 / requirements / python 3 / node / 零依赖 |
| 有平台兼容 / 泛化说明 | 关键词：兼容 / windows / macos / linux / 任意文件夹 / 任意路径 |

> **文档与代码分开计数**是刻意的：用「文档里出现绝对路径」的阈值去数代码里的路径，会让证据字符串变成误导。

### 可执行（Executable）

| 检查项 | 判定规则 |
|--------|----------|
| 含可运行代码 / 工作流 | 有代码文件或代码段，或 SKILL.md 含 `## Workflow / 工作流 / 步骤 / 流程` 章节 |
| 技能包结构合法 **（关键）** | 实测压缩包：zip 头 `PK` 或 gzip 头 `\x1f\x8b`，可解压，且**必须含 SKILL.md**，否则判伪包 |
| Python 源码语法可解析 | 对每个 `.py`（**含包内**的 .py）执行 `compile()`，抛 SyntaxError 即 ❌ |
| SKILL.md 有有效 frontmatter **（关键）** | 解析 `---` 块：需有 `name`，且 `description` ≥ 20 字符。支持 `>` / `|` 块标量 |

### 可验证（Verifiable）

| 检查项 | 判定规则 |
|--------|----------|
| 有测试用例或可复跑示例 | 关键词（测试/自测/assert/断言/示例/example）或文件名（run_selftest/self_test/test_/_test） |
| 写明了预期输出 / 结果 | 关键词：预期 / expected / 应输出 / 输出示例 / 结果如下 |
| Demo 存在且非空 **（关键）** | 存在 demo 类文件且 ≥32 B |
| 有明确的通过 / 失败判据 | 关键词：pass / fail / 判定 / 阈值 / 退出码 / ≥ |

> 注意：**demo 截图不算测试用例**。两者是独立检查项，不能互相顶替。

### IO 明确（Clear I/O）

| 检查项 | 判定规则 |
|--------|----------|
| 有「输入X，输出Y」一句话 **（关键）** | 正则 `输入…输出 / 接受…返回 / input…output / 给定…得到`；命中片段若含 `.*`、`___`、`XXX` 等**规范占位符则跳过**（避免匹配到规范本身） |
| 输入的类型 / 格式有说明 | 关键词：输入 / 参数 / input / argv / 接受 / 读入 |
| 输出的类型 / 格式有说明 | 关键词：输出 / 生成 / 产出 / 报告 / output / .md / .json / .csv |
| 说明了边界输入的处理 | 关键词：空文件夹 / 边界 / 缺失 / 异常 / edge case / 错误处理 |

## 四、红旗与封顶

| 红旗 | 严重度 | 触发条件 | 封顶 |
|------|--------|----------|------|
| 疑似敏感信息泄露 | critical | 正则命中 `sk-…` / `api_key = "…"` / `password = "…"` / `BEGIN PRIVATE KEY` / `AKIA…` | **40** |
| 核心交付物缺失 | high | ≥2 个交付物槽位为 ❌ **或为空壳** | 50 |
| 伪 .skill 包 | high | 压缩包无法解析或缺 SKILL.md | 55 |
| 空壳文件 | high | 存在 0 字节文件，或唯一命中文件 <32 B 且内容仅占位符 | 60 |
| 无 AI 使用记录 | high | ai_log 槽位缺失 | 65 |
| 无 Demo | medium | demo 槽位缺失 | 75 |
| 一句话指令直接提交 | medium | AI 日志中可识别的迭代轮次 ≤1 | 80 |
| 目录内含草稿 / 锁文件 | low | 命中 `~$*`、`_*`、`*.tmp`、`*.bak`、`.DS_Store` | 88 |
| 已排除测试夹具中的假密钥 | info | 假密钥位于 `examples/ fixtures/ tests/ demo-*` 等夹具路径，或紧邻 fake/sample/测试 等语境词 | 100（不扣分） |

> **夹具语境豁免是必需的，不是可选的。** 本评审器 v0.9 就曾把"提交包内自带测试夹具里的探针假密钥"判成真实泄露，
> 使一份优秀提交被错误封顶到 40 分。这个假阳性是实测发现的，详见交付包中的复盘 AAR。

---

## 五、同输入同输出

评审器全程无随机源。自测套件里有一条断言：同一输入连续跑两次，结果 JSON **逐字节一致**。
如果哪天这条断言红了，说明有非确定性来源被引入，必须先修再谈准确率。
